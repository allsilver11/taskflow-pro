# 01-product.md — 제품 정의

## 제품 목표

> **팀 업무를 시각화한다. "지금 누가 뭐 해?" 라는 질문이 사라지게 만든다.**

슬랙·이메일을 뒤지거나 팀원에게 물어보지 않아도,
지금 누가 어떤 업무를 맡고 있고 언제 끝나는지 한 화면에서 파악할 수 있다.

---

## 페르소나

| 항목 | 내용 |
|------|------|
| **대상** | 10명 규모 스타트업의 팀 리더 |
| **연령대** | 30~40대 |
| **핵심 불편** | 업무 현황을 파악하려면 매번 팀원에게 물어봐야 한다 |
| **기대** | 로그인하면 팀 전체 업무 상태가 한눈에 보인다 |
| **환경** | 노트북(업무용) + 스마트폰(이동 중 확인) |

---

## MVP 범위

### CRUD 4종 — 모든 동작이 화면에서 이뤄진다

| 동작 | 설명 |
|------|------|
| **추가(Create)** | 업무 제목, 상태, 마감 일시를 입력하고 저장 |
| **목록(Read)** | 전체 업무를 상태·마감일 기준으로 조회 |
| **수정(Update)** | 목록에서 직접 업무를 클릭해 인라인 또는 모달로 수정 |
| **삭제(Delete)** | 삭제 확인 후 제거 |

### 상태 분류

업무는 다음 4가지 상태 중 하나를 가진다.

| 상태 값 | 표시 레이블 |
|---------|-------------|
| `todo` | 할 일 |
| `in_progress` | 진행 중 |
| `review` | 검토 중 |
| `done` | 완료 |

### 마감 일시 (`due_at`)

- 날짜만이 아니라 **시간까지 지정한다.**
- 저장 형식: `YYYY-MM-DD HH:mm` (예: `2026-05-12 18:00`)
- 화면 표시도 시간 포함 (예: `5월 12일 오후 6:00`)
- 마감이 지난 업무는 시각적으로 구분 표시한다.

### 테마

- **라이트 / 다크 모드 토글** 지원
- 선택한 테마는 `localStorage`에 저장 → 새로고침 후에도 유지
- 시스템 기본값은 라이트 모드

### 반응형

- **최소 지원 너비: 360px** (스마트폰 기준)
- 360px에서 레이아웃이 깨지지 않아야 한다.
- 브레이크포인트: 모바일(~768px) / 태블릿(769px~1024px) / 데스크탑(1025px~)

## UI 톤 & 무드

Mac OS 스타일을 기준으로 한다.

| 요소 | 적용 방향 |
|------|-----------|
| **모서리** | 둥근 모서리 (`border-radius: 12px` 기준) |
| **그림자** | 부드럽고 퍼지는 그림자 (`box-shadow: 0 4px 24px rgba(0,0,0,0.08)`) |
| **카드** | 반투명 배경 (`backdrop-filter: blur`) |
| **폰트** | 시스템 폰트 스택 (`-apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif`) |
| **컬러** | 라이트: 흰/회색 계열 / 다크: 짙은 회색 계열, 강조 색 1개 |
| **애니메이션** | 상태 전환 시 짧고 자연스러운 transition (150~200ms) |

## 확장 계획 (MVP 이후)

MVP가 성공 기준을 충족한 후 순서대로 추가한다.

| 우선순위 | 기능 | 핵심 내용 |
|----------|------|-----------|
| 1 | **JWT 로그인** | 회원가입·로그인, 토큰 기반 인증 |
| 2 | **팀 기능** | 팀 생성, 멤버 초대, 업무 담당자 지정 |
| 3 | **Kanban 보드** | 상태 컬럼 간 드래그 앤 드롭 |
| 4 | **채팅** | 업무 단위 코멘트 스레드 |
| 5 | **CI/CD** | GitHub Actions 기반 자동 배포 |

---

## MVP 범위 외 (보류)

아래 기능은 MVP에 포함하지 않는다. 요청이 들어와도 확장 단계 전까지 구현하지 않는다.

| 항목 | 이유 |
|------|------|
| 외부 결제 | MVP 수익 모델 없음 |
| 네이티브 앱 (iOS/Android) | 웹 반응형으로 대체 |
| WebRTC (화상·음성) | 복잡도 대비 MVP 가치 낮음 |
| 외부 캘린더 연동 (Google 등) | OAuth 복잡도, MVP 이후 검토 |
| 파일 업로드 | 스토리지 인프라 필요, 확장 단계 |
| WebSocket (실시간 동기화) | **MVP는 폴링으로 대체**, 확장 단계에서 전환 |

## 성공 기준

MVP가 다음 4가지를 모두 만족하면 완료로 간주한다.

| # | 기준 | 측정 방법 |
|---|------|-----------|
| 1 | **새로고침 유지** | 테마·목록이 새로고침 후에도 동일하게 표시된다 |
| 2 | **360px 안 깨짐** | Chrome DevTools 360px에서 스크롤·레이아웃 이상 없음 |
| 3 | **API 응답 200ms** | CRUD 4종 각 엔드포인트 평균 응답시간 200ms 이하 |
| 4 | **CRUD 4종 화면 동작** | 추가·조회·수정·삭제가 페이지 이동 없이 화면에서 완결된다 |
| 5 | **테마 토글 작동** | 라이트↔다크 전환 후 새로고침해도 선택이 유지된다 |
